# 项目进度

## 当前版本

- [x] **0.1.51**（2026-07-30）：内网 DNS 分流。TUN 下内网域名不再被 Fake-IP 吞掉；
      DHCP 不下发搜索域时用内网 DNS 的 PTR 反解推断 AD 域（要求该域解析到私有 IP 防误判）。
      测试 344 通过 / 1 跳过 / 0 失败。**TUN 模式待用户真机验证**（需输一次密码重装助手）。

- [x] **0.1.47**（2026-07-29）：`default_domain_resolver` 改走无连接 UDP。
      原本指向 DoH，长连接被路由器 NAT 回收后 sing-box 察觉不到，而这条通道负责解析
      节点自己的域名 → 代理每 ~16 分钟停摆 10 秒。测试 314 通过 / 1 跳过 / 0 失败。
      **实机已复核生效**：修复后 3h19m 内只剩 1 次超时，周期性消失。
- [x] **0.1.46**（2026-07-29）：免密码助手每 30 秒 SIGTRAP 崩溃修复（Swift 6 顶层代码
      的 @MainActor 隔离 + 自建 dispatch 队列，编译期零提示）。导致 `checkClientLiveness`
      与优雅退出路径从未执行过。改为 C 信号处理器 + 单调时钟轮询，加源码层守卫测试。
      **实机已复核生效**：助手连续存活 5h14m，崩溃报告不再增加。
- [ ] **0.1.46 / 0.1.47 未推送、未发 Release**（本地领先 `origin/main` 两个提交，
      GitHub 最新仍是 v0.1.45）。
- [ ] **待修 A**：固定 mixed 端口的保证只是概率性的。`availableHighPort(preferred:)`
      对首选端口只探测一次、无重试，而端口池就是 macOS 临时端口范围
      → 一次瞬时占用就永久换端口（实机 2026-07-30 08:35 已发生：49609 → 65408），
      0.1.45 要治的「正在重新连接」会重现。
- [ ] **待修 B**：主 App 后台空闲曾烧 50% CPU 持续 178 秒（2026-07-30 04:43–04:46），

      属性导致全图失效；当前空闲基线 CPU 4–5.6% 也偏高。
- [x] **v0.1.45 已发布**（2026-07-28）：固定本地 mixed 端口，根治系统代理模式下
