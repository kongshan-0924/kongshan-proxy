## 运行优化优先级

1. **P1：处理 TAG 自动更新。** 修正 HTTP 401 对应的订阅凭据/地址，或关闭 TAG 自动更新。
2. **P1：菜单鼠标终验。** 观察速度变化，展开任一节点子菜单保持 10 秒并移动选择；关闭主窗口后从
   状态栏点击“打开仪表盘”。若均正常，本次菜单问题即可关闭。
3. **P1：真实换网验收。** 在 TUN 或系统代理运行中切换公司网、家庭网和手机热点，确认
   v0.1.62 能重探 LAN DNS、刷新 DoH 传输并自动恢复数据面。
4. **P2：继续观察 URL 全量测速。** 当前 16 并发、3 秒超时是响应速度与瞬时负载的平衡；只有真实使用
   仍经常超过 30 秒或出现明显输入卡顿时，再考虑可取消任务或按策略组测速，不继续盲目抬高并发。
5. **P2：继续观察极端日志量。** v0.1.61 未聚合日志突发是最高负载（平均 6.36%、峰值 15.9%），
   已通过门禁；只有真实使用中接近 2,000 行并持续高频流入时才需要继续优化。
6. **P2：旧日志清理。** `sing-box-tun.log` 15.7 MB 且已停用，现有“清理可再生缓存”会覆盖它；
   是否清理由用户在 UI 中决定，不自动删除。
7. **P2：TUN 助手。** App 更新会改变 ad-hoc cdhash；下次使用 TUN 若界面提示助手需重装，按 UI
   正常重装一次，绝不能放宽 helper 的 cdhash 校验。

## 已完成、不再列为待办

- 未生效订阅/节点变化不再重启当前内核；必须重建时会记录重载前后 PID、失败和回滚事件。
- 真实网络身份变化会通过 SystemConfiguration 获取物理接口，再从 DHCP 重探 LAN DNS；
  同时重建内核刷新 DoH 传输，避免继续使用旧网络上的连接。
- 消息页已提供最多 200 条、持久化且脱敏的运行事件，换网、睡眠唤醒和自动恢复可追溯。

## 长时间资源门禁

日常无需常驻额外监控。需要 1 小时只读采样时运行：

```sh
KONGSHAN_HEALTH_SAMPLE_COUNT=360 KONGSHAN_HEALTH_INTERVAL_SECONDS=10 scripts/verify_long_run_health.sh
```

脚本不启动、不停止、不重启 App，也不修改系统代理；超出 CPU/RSS/FD/CLOSE_WAIT 门槛时
会把诊断保存在 `/private/tmp`。

## 需要用户参与才能推进

- **睡眠唤醒的隧道自动重建**：合盖休眠 → 唤醒，看是否自动恢复；没恢复时关掉再开也应正常。
- **真实换网恢复**：代理运行中切公司网 / 家庭网 / 手机热点，核对运行事件、内网域名和外网访问。
- **经代理的出口 IP**：需换一个没有透明代理的网络（手机热点最省事）。当前家庭网络在做
  透明代理 + SNI 分流，判据见 `docs/design/tun-real-machine-debug.md`。

## 想彻底消掉「App 更新后要重装助手」

只有两条路，都需要付费 Apple Developer 账号：改用 NetworkExtension（Surge/Stash 的做法），
或用 Developer ID 签名把助手的认人方式换成签名 requirement（ClashX 的做法）。
**不要**为省这一次弹窗放宽 cdhash 校验——ad-hoc 的 identifier 谁都能伪造。
详见 `docs/design/tun-authorization-approaches.md`。

## 暂不扩张

- 不加 TUIC / WireGuard，除非真实订阅出现需求（内核已支持，缺的只是转换分支）。
- 不引入 Sparkle；private 仓库没有可安全匿名访问的更新源。
- 不为拆文件而重写 `AppState`；只随真实功能按领域拆 extension。
