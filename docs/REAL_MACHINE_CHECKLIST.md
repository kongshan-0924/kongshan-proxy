# 真机验收清单（长期观察项）

> 用途：这三项都需要真实网络环境与人工操作，无法由自动化完成。
> 按顺序逐项做，每项做完把结果记回 `docs/progress/SESSION_LOG.md`。
> 前置：当前安装版为 v0.1.81（build 181）或更新的 v0.1.82；TUN 助手已重装。

## 1. 睡眠唤醒后隧道自动重建

**前置条件**：TUN 模式运行中（或系统代理 + TUN 双开）。

**操作步骤**：

1. 确认代理开启、网页可正常打开（找一个会持续刷新的页面，或开着视频）。
2. 合盖休眠，等待 1 分钟以上。
3. 开盖唤醒，观察：
   - 菜单栏图标是否仍显示代理开启状态；
   - 网页/视频是否自动恢复，无需手动重连；
   - 消息页运行事件是否出现「系统已唤醒」和（如有必要）「网络变化已应用」。

**判定标准**：

- 唤醒后 30 秒内数据面恢复（curl 经代理 200，或页面自动续传）＝ 通过。
- 若唤醒后打不开网页，先看消息页事件；再关掉代理重开一次，若恢复则把
  「唤醒后需手动重启」记回 SESSION_LOG——这是已知边界，不是必改缺陷。

**排查入口**：消息页运行事件时间线（脱敏）；`~/Library/Application Support/kongshan/logs/sing-box.log`。

## 2. 真实换网恢复（LAN DNS 重探 + DoH 传输刷新）

**前置条件**：系统代理或 TUN 运行中；手头能切换的网络至少两种
（公司网 / 家庭网 / 手机热点任选两组）。

**操作步骤**：

1. 在代理运行中切换网络（如 Wi-Fi → 手机热点）。
2. 切网后观察：
   - 消息页是否出现「物理网络已变更」→「网络变化已应用」两条事件；
   - 内网域名（若有，如公司 AD 域）是否仍能解析、内网设备能否访问；
   - 外网（Google/GitHub 等）是否恢复。
3. 换回原网络再重复一次。

**判定标准**：

- 每次切网后消息页有「物理网络已变更」+「网络变化已应用」两条事件 ＝ 重探链路生效。
- 切网后 30 秒内外网恢复；内网域名解析正确（`dig` 返回真实内网 IP 而非 240.x）＝ 通过。
- 若切网后外网恢复但内网域名解析仍用旧 DNS，把现象记回 SESSION_LOG——
  TUN 运行中换网的 LAN DNS 重探是 v0.1.62 起的重点验证项。

**排查入口**：消息页运行事件；`scutil --dns`（检查 DNS 指向）；内网探测逻辑见
`Sources/KongshanCore/LANResolver.swift`。

## 3. 无透明代理网络下的出口 IP 验证

**背景**：当前家庭网络在做透明代理 + SNI 分流，判据见
`docs/design/tun-real-machine-debug.md`。该环境下任何代理客户端的节点都连不上
（TCP 握手 3~4ms 假象、Reality verification failed），**必须换网络才能验证**。

**操作步骤**：

1. 切换到手机热点（或任何非透明代理的网络）。
2. 开启代理（系统代理或 TUN 均可），在仪表盘「出口诊断」卡刷新出口 IP。
3. 与直连时的出口 IP 对比：
   - 开启代理后出口 IP 应变为**节点所在地**（如 LA 节点 → 美国 IP）；
   - 关闭代理后恢复本机运营商 IP。

**判定标准**：

- 代理开启出口 = 节点所在地、关闭 = 本机 IP ＝ 通过。
- 若开启后仍显示本机 IP 或直连国外出口 = 节点没走通，把节点名与日志尾部
  记回 SESSION_LOG。

**排查入口**：仪表盘「出口诊断」卡（含 DNS 三态结论）；内核日志的
`reality verification failed` 是否出现（出现即网络在做透明代理，不是 App 问题）。

## 附带观察（顺手记，不阻塞）

- **菜单鼠标**：展开任一节点子菜单停留 10 秒不闪烁、可选择；关闭主窗口后从状态栏
  「打开仪表盘」有效。
- **节点失败率阈值**：消息页若出现「节点建连失败」告警，记下节点名、失败比例与
  原因——用于回调 `OutboundFailureDetector` 阈值（当前 600s / ≥20 尝试 / ≥5 失败 / ≥10%）。
- **DNS 解耦入口**（v0.1.82 起）：若真实使用中偶发「节点域名解析」超时，可在
  设置 → DNS 高级设置 填入独立引导解析器 IP（如 `114.114.114.114`）与国内 DoH 解耦。
