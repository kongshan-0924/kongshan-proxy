# 单一侧栏按钮修复设计

> 状态：已由 `2026-07-22-fixed-sidebar-toggle-position-design.md` 补充修订。0.1.21 人工验收确认原生按钮虽不再重复，但侧栏折叠后会迁到标题栏最右侧。

## 问题

0.1.20 在 `NavigationSplitView` 自带侧栏按钮之外，又增加了一个用于图标紧凑模式的自定义工具栏按钮。代码尝试在窗口创建后删除系统按钮，但 SwiftUI 会异步重建工具栏，删除动作早于系统按钮最终插入，因此仪表盘和其他页面会同时出现两个相同图标。

## 决策

只保留 macOS 原生侧栏按钮。删除自定义紧凑侧栏状态、按钮和图标列表分支，同时删除 AppDelegate 中依赖时序的系统按钮清理代码。

不增加 AppKit 监听器、延时重试或私有 API。原生按钮负责显示和隐藏完整侧栏，行为与其他 macOS 应用一致。

## 修改范围

- `MainWindowView.swift`：删除 `isSidebarCompact`、自定义 toolbar、紧凑行和相关条件布局，恢复单一完整侧栏。
- `KongshanApp.swift`：删除 `removeSystemSidebarToggle` 及其调用，让系统按钮正常存在。
- 测试：锁死主窗口不再声明自定义侧栏 ToolbarItem、紧凑状态或 AppKit 时序清理；命令行 XCTest 不暴露 SwiftUI Scene 标题栏，打包 App 的单按钮结果保留人工视觉确认。

不修改 AppState、代理内核、系统代理、TUN、订阅或持久化逻辑。

## 验收标准

1. 仪表盘、设置及其他页面只显示一个侧栏按钮。
2. 点击按钮可以正常隐藏和重新显示侧栏。
3. 全量测试、构建和打包通过。
4. 新产物安装后版本可正常启动，代理相关状态不被触发或修改。
