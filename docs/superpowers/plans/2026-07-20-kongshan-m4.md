# kongshan M4 打磨实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox syntax for durable tracking.

**Goal:** 完成 Dashboard 实时指标与 60 秒曲线、日志查看/导出、双 DoH DNS、开机自启、订阅定时更新、内核崩溃自愈和性能红线验收，在不引入轮询、大型依赖或新增敏感落盘的前提下交付完整 arm64 App。

**Architecture:** `ConfigGenerator` 继续保持纯函数，DNS 作为可验证的值类型注入；Clash REST 与 WebSocket 均只使用随机内存 secret。Dashboard 和日志各自持有可取消的 WebSocket 任务，View 消失立即断开。普通/TUN 内核统一使用进程退出事件监控，`CrashRestartLimiter` 只允许 10 秒滚动窗口内自动重启 3 次。订阅更新使用一次性 sleep 后重排的 scheduler，不做周期轮询。所有系统服务、通知、时钟与流都可注入，自动测试不注册登录项、不发真实通知、不改网络、不请求 TUN 授权。

**Tech Stack:** Swift 6 strict concurrency, SwiftUI/macOS 14, Swift Charts, Foundation `URLSessionWebSocketTask`, ServiceManagement `SMAppService.mainApp`, UserNotifications, Dispatch process source, bundled sing-box 1.13.14, XCTest, existing Yams only.

## 已核验边界与决策

- sing-box 1.13.14 的新 DNS server 格式使用 `type: https`、`server`、`path`、`tls` 与 Dial Fields；DNS 规则使用 `action: route` + `server`。
- 多 DNS server 时必须设置 `route.default_domain_resolver`。它用于代理节点服务器域名的 bootstrap，固定走国内 DoH/direct；若设成经代理的远程 DoH，会与“先解析代理节点才能连接代理”形成循环。
- 用户查询：`geosite-cn → dns-cn`，其余 `dns-remote`；`dns-cn` 的 `detour=direct`，`dns-remote` 的 `detour=自动选择`。默认服务器均使用需求指定的 IP DoH，避免 DoH 自身域名再次 bootstrap。
- TUN route 在业务分流规则前加入 `sniff` 与 `protocol=dns / action=hijack-dns`；系统代理只能保证进入 mixed inbound 的域名解析使用该 DNS，不把它夸大成操作系统全局 DNS 接管。
- 默认不生成 `fakeip`；设置页明确兼容性优先。
- 打包内核 v1.13.14 源码确认：`/traffic` WebSocket 每秒推送 `up/down`；`/connections` 推送 `downloadTotal/uploadTotal/connections/memory`；`/logs?level=` 推送 `type/payload`；Bearer header 或内存 token 均可认证。
- Dashboard 使用 `/traffic` 和 `/connections?interval=1000`，不通过定时 REST 轮询；内存取 `/connections` 的 `memory`。
- 普通与 root TUN 都以 PID 注册 `DispatchSourceProcess(.exit)`；主动 stop/reload 前先取消监控，避免误判崩溃。TUN 自动重启仍会出现明确管理员授权弹窗。
- `SMAppService.mainApp.register/unregister` 只响应用户开关；自动测试只用 fake manager。ad-hoc/非 Applications 路径下的系统批准行为保留人工验收。
- 本地通知只用于订阅失败和崩溃终止；按需请求权限，拒绝通知权限不影响代理主功能。

## 执行不变量

1. 每个功能 Task 先写失败测试并观察预期 RED，再写最小实现。
2. 自动测试不得调用真实 `networksetup`、`osascript ... administrator privileges`、`SMAppService.register` 或 `UNUserNotificationCenter.add`。
3. Dashboard/日志页面不可见时没有 WebSocket；禁止用 Timer/循环 REST 请求刷新流量、连接或内存。
4. 曲线最多保留 60 个一秒样本，日志内存缓冲设置固定上限，所有长生命周期 Task 都必须可取消。
5. Clash controller 仅监听 127.0.0.1；secret 只存在内存，不写日志、设置、诊断配置或导出元数据。
6. 所有配置重启仍执行 prepare rule-set → pure generate → `sing-box check` → 切换/健康检查 → 失败回滚。
7. M4 每个 Task 完成后立即追加 SESSION_LOG，更新 HANDOFF/PROGRESS/NEXT_STEPS，并与代码同提交。
