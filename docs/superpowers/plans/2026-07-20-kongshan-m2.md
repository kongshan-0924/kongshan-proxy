# kongshan M2 分流实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox syntax for durable tracking.

**Goal:** 在 M1 系统代理基础上实现固定六级分流、官方 `.srs` 缓存、自定义规则编辑器、route/系统 bypass 双处注入和不断开系统代理的快速重启。

**Architecture:** 规则数据使用 Codable/Sendable 值类型并原子存入 `rules.json`；`ConfigGenerator` 继续保持纯函数，只接收已准备的本地 rule-set 路径。`RuleSetService` 负责下载、用官方 sing-box 解析验证、原子替换和旧缓存兜底。规则改动时先生成并 `check` 新配置，再在相同内存端口/secret 上快速重启，系统代理不先关闭；失败回滚旧配置与 bypass。

**Tech Stack:** Swift 6 strict concurrency, SwiftUI/macOS 14, Foundation, XCTest, bundled sing-box 1.13.14, existing Yams only.

---

## 已核验的 1.13.14 边界

- route 规则使用 `action: "route"` + `outbound`；自定义类型对应 `domain_suffix` / `domain_keyword` / `domain` / `ip_cidr` / `process_name`。
- 私有地址使用 1.13 可用的 `ip_is_private: true`，不再使用已移除的旧 GeoIP 数据库。
- 本地 binary rule-set 结构为 `type: local`, `format: binary`, `path: ...`；本地文件更新在 sing-box 1.10+ 可自动重载，但完整 route 改动仍采用快速重启。
- 官方资源 URL 已实时确认 HTTP 200：`geosite-cn.srs`、`geoip-cn.srs`、`geosite-category-ads-all.srs`。
- sing-box CLI 无完整配置 reload 命令；需满足的需求允许“重载或快速重启”，因此不伪造信号 API。

## 执行不变量

1. 每个 Task 必须先写失败测试，观察预期 RED，再写最小实现。
2. 每个 Task 完成后立即追加 `docs/progress/SESSION_LOG.md`，更新 HANDOFF/PROGRESS/NEXT_STEPS，并与代码放入同一提交。
3. 自动测试不得真实修改本机系统代理；`SystemProxyManager` 继续使用命令记录器。
4. 下载的 `.srs` 必须先由官方 sing-box 成功解析，再替换成功缓存；任何失败不覆盖旧文件。
5. 热重启必须复用当次 `mixedPort` / `clashPort` / `secret`，不将 secret 写盘，不在重启前关闭系统代理。
6. 中断时先写清“已完成 / 未完成 / 下一步”，不留未记录半成品。

## M2 完成标准

- 六级 route 顺序、自定义规则字段和 route/system bypass 均有单测。
- 官方三个 `.srs` 只在解析成功后替换缓存，断网/坏内容使用最后成功缓存。
- 运行中规则改动不先关闭系统代理，可回滚旧配置与 bypass。
- 主窗口可编辑、排序、启停规则与维护两类 bypass。
- `zsh scripts/verify_m2.sh` 输出 `M2 automated verification passed`，`dist/kongshan.app` 仍为可签名 arm64 产物。
- 真实网络验收未执行时必须明确标记，不得用 fixture 代替。
