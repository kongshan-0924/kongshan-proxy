# kongshan M3 TUN 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox syntax for durable tracking.

**Goal:** 在不依赖付费开发者账号或 Network Extension entitlement 的前提下，为 kongshan 增加管理员授权启动的 macOS TUN、IP/CIDR 路由排除、strict_route 开关和系统代理/TUN 完整互斥状态机。

**Architecture:** `ConfigGenerator` 继续是纯函数，通过模式输入生成 mixed 或 tun inbound；TUN 使用 `auto_route`、`route.auto_detect_interface` 和用户 bypass CIDR。独立 `PrivilegedLauncher` 只负责安全构造 AppleScript、通过 0600 FIFO 向 root sing-box 传递内存配置、验证 PID、保存无 secret 的恢复记录并授权停止。`AppState` 持有首选/活动模式，切换时先完整停止旧模式，再启动新模式；所有自动测试注入 authorizer，绝不弹管理员授权或创建真实 TUN。

**Tech Stack:** Swift 6 strict concurrency, SwiftUI/macOS 14, Foundation, Darwin POSIX FIFO, `/usr/bin/osascript`, bundled sing-box 1.13.14, XCTest, existing Yams only.

---

## 已核验的 1.13.14 与 macOS 边界

- 官方 TUN inbound 支持 Linux、Windows、macOS；1.13.14 使用 `address`，不使用已移除的 `inet4_address/inet6_address`。
- `auto_route: true` 设置默认路由；TUN 配置同时设置 `route.auto_detect_interface: true`，防止代理 outbound 回流 TUN。
- `route_exclude_address` 是 1.10+ 正式字段，用于在 `auto_route` 下排除 IP/CIDR；域名无法静态转为操作系统路由，仍由已有高优先级 route direct 保证 TUN 下直连。
- `strict_route` 字段在 1.13.14 可通过 `check`；官方当前只明确描述 Linux/Windows 的额外语义，UI 仅提示“更严格、可能影响局域网”，不宣称 macOS DNS 防泄漏。
- 非特权 TUN 不会自动配置地址/MTU；MVP 按用户硬性要求使用 `do shell script ... with administrator privileges`，未来迁移到 `SMAppService` helper 或 Network Extension，不实现未授权 entitlement。
- Apple 文档说明 `do shell script` 使用 `/bin/sh`，授权有效期仅属于该脚本且约五分钟；所有 root shell 命令必须使用绝对路径、固定环境和严格引用。
- M3 不实现 DNS 高级设置；国内/远程 DoH、防泄漏实测按原里程碑留到 M4，不以 TUN 自动捕获替代。

## 执行不变量

1. 每个 Task 先写失败测试并观察预期 RED，再写最小实现。
2. 自动测试不得运行真实 `osascript ... administrator privileges`、不得创建真实 TUN、不得修改系统代理。
3. root 命令只允许固定动作：启动打包内核或向已验证 PID 发送 `INT`；路径和 PID 不允许未经校验拼接。
4. 完整配置只经 0600 FIFO 进入 root 进程 stdin；`tun-recovery.json` 只保存 PID、内核规范路径、时间，不保存配置、节点凭据、端口或 Clash secret。
5. TUN 启动前仍由普通用户进程执行 `sing-box check`；只有 check 成功才请求管理员授权。
6. 模式切换先完整关闭旧模式。新模式失败时回到关闭/failed，不同时保留 system proxy 与 TUN。
7. 每个 Task 完成后立即追加 SESSION_LOG，更新 HANDOFF/PROGRESS/NEXT_STEPS，并与代码同提交。

纯构造器 API：

```swift
public enum PrivilegedCommandBuilder {
    public static func start(binaryURL: URL, fifoURL: URL, logURL: URL) -> String
    public static func stop(pid: Int32, binaryURL: URL) throws -> String

```

测试包含空格和单引号路径；启动脚本必须只使用 `/bin/cat`、打包内核绝对路径、`run -c /dev/stdin`、日志重定向和 `with administrator privileges`。停止脚本必须在 root shell 内用 `/bin/ps -p <pid> -o command=` 再次匹配规范内核路径后才 `/bin/kill -INT <pid>`；PID ≤ 1、非数字输出均拒绝。

- [x] **Step 2: 运行测试确认构造器缺失失败**

Run: `swift test --filter PrivilegedLauncherTests`

- [x] **Step 3: 实现固定命令白名单与 AppleScript 转义**

不暴露“任意 shell 命令”API。shell 单引号使用标准 `'<value with '\'' escapes>'`，AppleScript 字符串再转义反斜杠与双引号。命令首部固定 `umask 077; PATH=/usr/bin:/bin:/usr/sbin:/sbin`。

- [x] **Step 4: 实现并测试 POSIXConfigPipe**

公共值类型与 actor：

```swift
public struct PrivilegedProcessRecord: Codable, Equatable, Sendable {
    public let pid: Int32
    public let binaryPath: String
    public let launchedAt: Date
}

public actor PrivilegedLauncher {
    public func start(config: Data) async throws -> PrivilegedProcessRecord
    public func stop() async throws
    public func recoverIfNeeded() async throws
}
```

注入 `Authorizer`、`ConfigTransport`、`ProcessInspector`。成功启动必须先验证 PID 对应命令含规范内核路径，再原子写 `tun-recovery.json`；任何失败不得留下记录。停止成功或确认进程已不存在后删除记录；PID 对应其他进程时删除陈旧记录但绝不发送 kill。

## M3 完成标准

- TUN config 使用 1.13.14 正式字段并通过 strict 关/开真实 `check`。
- bypass CIDR 同时存在于 route direct 和 TUN `route_exclude_address`；域名在 TUN 下由 route direct 保证，不伪造静态域名路由排除。
- root 命令面只允许启动打包内核和停止已二次验证 PID；配置/secret 不落盘。
- system proxy/TUN 互斥切换、启动失败、退出失败和崩溃恢复都有自动测试。
- `zsh scripts/verify_m3.sh` 输出 `M3 automated verification passed`，`dist/kongshan.app` 为 ad-hoc 签名 arm64 产物。
- 未执行管理员授权或真实 TUN 时明确标记，绝不以 `sing-box check` 代替出口 IP/DNS/恢复验收。
