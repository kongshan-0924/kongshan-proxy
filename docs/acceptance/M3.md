- 纯配置测试证明 bypass CIDR 同时进入 route direct 与 TUN `route_exclude_address`；bypass 域名保持 route direct，不伪造成静态地址路由。
- 提权命令构造测试覆盖 shell/AppleScript 引用、固定命令白名单、非法 PID 拒绝与 PID 对应内核路径复核。

- 生命周期测试覆盖授权取消、坏 PID、启动记录、停止失败保留、陈旧记录清除、重启恢复与敏感值不落盘。

- 所有系统代理测试使用命令记录器；所有特权测试使用 fake authorizer/launcher。自动验收脚本不调用 `osascript`、不请求管理员授权、不运行 `sing-box run`，也不创建真实 TUN。

## 未执行的人工验收

以下项目会请求管理员授权、改变真实路由或依赖真实节点，本次未自主执行：

1. 在 Dashboard 选择 TUN 并开启代理，确认出现 macOS 管理员授权弹窗，授权后出现预期 utun 接口。
2. 使用真实节点执行 `curl https://ifconfig.me`，确认 TUN 开启后为代理出口 IP；关闭后恢复本地出口 IP。
3. 配置一个 bypass 域名与一个 bypass CIDR，分别验证域名经 route direct、CIDR 不进入 TUN，并核对实际连接路径。
4. 关闭 TUN，确认 utun 路由不再接管、root sing-box 退出、应用状态回到关闭且无恢复记录。
5. 分别启用/关闭 strict_route，验证局域网服务、虚拟机、容器和其他 VPN 软件的兼容性。
6. TUN 活跃时强制结束 kongshan，再次启动，验证恢复流程能够识别并经授权停止遗留 root 进程。
7. 在浅色/深色模式下人工检查 Dashboard、设置页的模式切换、strict 警告和菜单栏关闭/system/TUN 图标。
