# kongshan 空山

一款面向 Apple Silicon Mac 的原生、轻量 sing-box 图形客户端。

空山使用 SwiftUI + AppKit 构建，内置官方 sing-box 1.13.14，不自行实现代理协议或加密算法。它以“配置”为中心，支持系统代理与 TUN 单独或同时运行，重点解决日常使用中最实际的几个问题：切换要快、菜单要稳、资源要轻、退出后网络必须恢复。

[下载最新版本](https://github.com/kongshan-0924/kongshan-proxy/releases/latest)

## 主要功能

| 功能 | 说明 |
|---|---|
| 配置管理 | 导入 Clash YAML 订阅，一个订阅对应一个配置；支持快速切换、缓存和定时更新 |
| 节点支持 | Shadowsocks、Trojan、VMess、VLESS、Hysteria2、AnyTLS |
| 代理模式 | 系统代理、TUN，可单独开启或同时开启；支持规则、全局、直连出站模式 |
| 策略组 | 沿用订阅中的策略组，支持节点切换、批量测速、取消测速和自动选择最快节点 |
| 自定义规则 | 强制代理域名、IP、CIDR；自定义绕过；按应用进程分流；内网网段排除 |
| 运行监控 | 实时速度、会话流量、活跃连接、出口 IP、DNS 检测、内核内存和运行时长 |
| 连接与日志 | 查看目标、进程、命中规则和完整出站链路；日志筛选、搜索和按连接聚合 |
| 菜单栏 | 显示代理状态和整机上下行速度，可直接切换模式、策略和节点 |
| 恢复与诊断 | 系统代理/DNS 自动恢复、崩溃自愈、换网与睡眠唤醒恢复、脱敏诊断导出 |

## 使用步骤

### 1. 安装

从 [Releases](https://github.com/kongshan-0924/kongshan-proxy/releases) 下载最新 DMG，打开后把 `kongshan.app` 拖入“应用程序”。

当前发布包使用 ad-hoc 签名，没有 Apple Developer ID，也未公证。首次启动请在“应用程序”中右键 `kongshan.app`，选择“打开”。

### 2. 导入配置

打开“配置”页面，粘贴 Clash YAML 订阅链接并导入。也可以：

- 批量粘贴 `ss`、`trojan`、`vmess`、`vless`、`hysteria2`、`hy2` 或 `anytls` 节点链接；
- 手动添加 Hysteria2 节点；
- 在多个本地配置之间快速切换。

订阅内容和本地设置默认保存在：

```text
~/Library/Application Support/kongshan/
```

### 3. 选择节点

进入“代理”页面，在订阅策略组中选择节点。可以先运行“测速全部”，也可以使用“测速并自动选最快”。测速任务支持进度显示和取消，不会逐个刷新整页阻塞操作。

### 4. 开启代理

- **系统代理**：适合浏览器和遵循 macOS 代理设置的应用，开启快、开销低。
- **TUN**：接管更多不读取系统代理的应用流量，并提供完整 DNS 分流。
- 两者可以同时开启，系统代理入口保持不变。

### 5. 可选：安装 TUN 助手

第一次使用 TUN 会需要管理员授权。可以在“设置 → 隧道”安装免密码助手，授权一次后，日常启停 TUN 不再重复弹出密码框。

App 更新后签名指纹可能变化，界面提示“需重装”时重新安装一次即可。助手的签名和路径校验不能绕过。

### 6. 正常关闭

从菜单栏退出空山即可。程序会先停止内核，再恢复系统代理和 DNS；如果上次异常结束，下次启动也会优先尝试恢复遗留设置。

## 特色功能

### 稳定的系统代理入口

系统代理始终连接由 App 持有的本地 TCP relay。普通模式和 root TUN 内核使用各自独立的内部端口，切换模式时只更换 relay 后端，不再让不同权限的 sing-box 争抢同一个监听端口。

这样可以避免模式切换时端口漂移、浏览器反复重连，以及系统代理暂时指向失效端口造成的断网。

### 有实时速度、但不会闪烁的原生菜单

菜单栏使用 AppKit 原生 `NSStatusItem + NSMenu`。整机速度每两秒更新，但不会重建正在展开的菜单，因此节点子菜单可以稳定停留和选择，“打开仪表盘”也不会因周期刷新失效。

速度读取物理 `en*` 网卡，不重复统计 TUN 流量，代理关闭时也能继续显示整机网速。

### 为轻量和流畅做过专门优化

- 仪表盘指标合并发布，曲线降低刷新频率；窗口不可见时停止无意义的图表更新；
- Clash API 使用推流而不是高频轮询，页面离开后及时释放非必要任务；
- 日志批量更新并限制数量，避免高频日志反复重绘界面；
- 批量测速采用有界并发、分批更新和可取消任务；
- 配置、规则和节点切换尽量热更新，必须重启内核时提供失败回滚。

### 强制代理与规则诊断

可以把指定域名、单个 IP 或 CIDR 强制交给某个代理策略，也可以按应用进程分流。规则页提供本地命中测试，连接页可以直接查看某条连接命中了什么规则、经过哪些策略和节点。

这类规则优先于订阅分流和中国大陆直连规则，适合处理下载站、数据库、企业服务或特定客户端没有按预期走代理的问题。

### 面向真实网络环境的 TUN

- 固定使用 gVisor 用户态网络栈；
- 使用 Fake-IP，并持久化映射；
- 系统 DNS 指向 TUN 接口自身地址；
- 启动前探测局域网 DNS，避免企业内网域名被错误送往代理节点；
- 换 Wi-Fi、切热点或睡眠唤醒后，重新检查网络身份、LAN DNS、DoH 连接和 TUN 接口。

### 安全、可恢复的特权助手

免密码助手只负责启动和停止内置 sing-box，不接受任意命令或路径。它会校验 App 身份、bundle 路径、签名指纹、内核指纹和配置白名单；配置通过只读文件描述符传递，不写入命令行。

系统代理和 DNS 在接管前都会保存原始快照。启动失败、配置重载失败、内核崩溃或正常退出时，会按状态回滚，避免留下指向失效端口的系统设置。

## 系统要求与限制

- Apple Silicon Mac（arm64）
- macOS 14 或更高版本
- 当前发布包为 ad-hoc 签名，首次打开和 App 更新后的助手授权受 macOS 安全策略影响
- TUN 固定使用 gVisor + Fake-IP；同时运行多个 TUN/VPN 客户端可能互相争抢路由
- 系统代理只能影响遵循 macOS 代理设置的应用；需要完整接管和 DNS 分流时请使用 TUN
- 项目不提供代理节点，请使用自己的合法订阅或自建节点

## 数据与隐私

- 订阅、规则、设置、节点和日志保存在本机 Application Support 目录；
- Clash API 端口与 secret 只保存在内存；
- `config.json` 是去除凭据后的诊断快照；
- 诊断导出不会包含订阅 URL、节点密码或完整配置；
- 应用没有账号系统和内置云同步。

## 本地构建

需要 Xcode Command Line Tools 和 Swift 6 工具链。

```bash
zsh scripts/build_app.sh       # 构建 .build/kongshan.app
zsh scripts/make_dmg.sh        # 生成 dist/kongshan-<版本>.dmg
zsh scripts/verify_m4.sh       # 完整测试、签名与资源门禁
zsh scripts/release.sh prepare # 生成与当前 Git 提交绑定的发布候选
```

构建 App 位于 `.build`，`dist` 只保留最新 DMG。正式使用时请只运行 `/Applications/kongshan.app`，避免同时启动多个副本。
